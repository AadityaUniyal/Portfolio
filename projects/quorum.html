01 — THE QUESTION

How do you make extracted information easier to challenge?

A useful document workflow needs to show what it found, how it checked it, and where a reviewer can confirm it.

Language models can help interpret inconsistent documents, but they are probabilistic. For financial review, a plausible total is not a verified total. For any extracted field, a reviewer should be able to return to the relevant part of the source.

Quorum OS is my exploration of that combined problem: organize multiple interpretations, add deterministic checks where the math is known, and preserve a path back to the evidence.

02 — THE SYSTEM

Different kinds of uncertainty get different checks.

The repository separates document intake, agent orchestration, arithmetic verification, and provenance generation. The interface can then present a finding alongside the information used to derive it.

03 — ENGINEERING CHOICES

Don’t ask one model to be the source of truth.

01

Route work by responsibility

The orchestration layer calls separate agents and includes category-aware weighting. That creates room to treat invoices, contracts, and other document types differently.

↗
02

Make consensus a replaceable strategy

The domain layer defines vote and decision objects alongside pluggable consensus strategies. Agreement and confidence are part of the result, so the system can surface uncertainty instead of hiding it.

↗
03

Use deterministic math for arithmetic

The SMT arithmetic verifier uses Decimal values and explicit constraints for invoice checks. This narrows the role of model output when a calculation can be stated precisely.

↗
04

Anchor values to source material

The Merkle provenance service computes field hashes with bounding-box and raw-token inputs. That record is designed to make source association inspectable and tamper-evident.

↗

04 — WHAT I’M TAKING FORWARD

Confidence should come with a way to inspect the work.

The product challenge is not only extracting fields. It is helping a person decide what deserves attention next.

Building Quorum OS has pushed me to think in boundaries: language models for interpretation, deterministic routines for arithmetic, and provenance structures for source association. Each contributes a different kind of signal.

The next design challenge is making disagreement legible. A strong review experience should let someone compare the competing values, jump to their source locations, and understand exactly which checks passed or remain uncertain.
